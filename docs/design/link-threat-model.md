# Reins Link 威胁模型

状态：第 2 版，2026-11-02。协议见 [link-protocol.md](link-protocol.md)。0.11.0 只有单机消息，没有任何网络入口，所以这里和网络有关的对策（T1、T6、T8、T10、T12、T17、T18）在多机实现时才生效。已生效的是 T2、T3、T11、T13、T14 和 T16。

修改 Link 的认证、权限、配对、端口监听或远程启动时，必须对照本文。行为变化要同时更新本文。

## 1. 为什么 Link 风险高

Reins 现在只在本机账号内工作。Link 会带来两个新变化：

- 一个网络入口：接收方可能是一个持有 shell 权限、甚至跳过审批的 Agent。
- 一条影响模型的通道：对端发来的文字会被另一个 Agent 读到。

所以**能发消息的对端就有机会影响接收 Agent 的行为，能启动 Agent 的对端几乎等于能在该账号下执行命令。** 后续设计都从这两点出发。

## 2. 要保护的东西

| 资产 | 说明 |
|---|---|
| 账号的执行权限 | Agent 能运行命令、改文件 |
| 节点私钥和 `peers.yaml` | 可用于冒充节点或给自己加权限 |
| 会话环境文件 | `queue/environments/*`，可能含凭证 |
| 任务日志、报告、消息正文 | 可能含代码和凭证 |
| 工作目录、会话 ID、主机信息 | 帮助攻击者定位目标 |
| API 额度和机器资源 | 可被循环对话或消息洪水耗尽 |

## 3. 攻击者

| # | 攻击者 | 能力 |
|---|---|---|
| A1 | 网络上的陌生人 | 能连上监听端口，能监听或篡改未加密流量 |
| A2 | 同机器的其他 OS 用户 | 能连回环端口，能看到进程列表 |
| A3 | 被攻破的对端节点 | 持有合法凭证，能发任意帧 |
| A4 | 被提示词注入的 Agent（本机或对端） | 能以该账号身份运行命令，能发消息 |
| A5 | 恶意或有缺陷的 PR | 能修改代码、测试和 CI 配置 |
| A6 | 失控的合法 Agent | 没有恶意，但会不停互发消息 |

## 4. 信任边界

```text
   不可信网络
───────────────────────────────  边界 1：TLS + mTLS，或 SSH
   Link 服务（只能写 link/ 下的文件）
───────────────────────────────  边界 2：文件校验（塔台不信任 inbound/ 的内容）
   塔台（queue/** 的唯一写入者）
───────────────────────────────  边界 3：信封（模型不应把正文当指令）
   接收 Agent
```

**同一 OS 账号内不是安全边界。** 同账号下的进程都能读 `~/.reins`，能伪造本机的 `reins send`。0600 权限只能防其他用户。第 7 节列出了这带来的残余风险。

## 5. 威胁与对策

| # | 威胁 | 攻击者 | 对策 | 测试 |
|---|---|---|---|---|
| T1 | 未认证连接发帧或探测 | A1、A2 | 先完成传输层认证，失败的连接读不到任何帧；错误信息不透露是否有此对端；默认不监听网络 | S1、S2 |
| T2 | **消息正文提示词注入** | A3、A4 | 正文放进 `details` 文件，并标注为对端内容；信封只含校验过的字段；对端内容不能设置审批、沙箱或工具权限 | S3、L6 |
| T3 | 信封注入：仿造 `[reins]` 行或 ACK 命令 | A3、A4 | `subject` 和名字严格校验、禁止换行；ACK 命令只由接收节点生成 | L6 |
| T4 | 冒充其他节点或会话 | A3 | `from.node` 由已验证的连接身份决定；`from.name` 显示为“对端声称”，并带节点别名 | N9、S4 |
| T5 | 权限提升：`hello` 声称有 `spawn`、请求放宽沙箱 | A3 | 权限只来自本节点的 `peers.yaml`；`spawn` 默认关闭、只能启动白名单专家；请求只能收紧沙箱 | S5、S6 |
| T6 | 窃听或篡改流量 | A1 | 只允许 TLS 1.2+ 和 SSH；不提供明文 TCP 选项 | S7 |
| T7 | 重放或 ID 撞车 | A1、A3 | TLS 防重放；消息层按 `(节点, ID)` 去重，相同 ID 不同内容拒绝；本地根由节点和 ID 的哈希生成，对端不能占用别人的记录 | N4、N5、N10 |
| T8 | 配对码被截获或重用 | A1 | 128 位以上随机、10 分钟过期、只能用一次；连接时校验配对码内的证书指纹；连续失败 5 次后作废；配对码不写入日志 | S8 |
| T9 | 私钥或对端配置被其他用户读取 | A2 | 目录 0700、文件 0600；启动时检查权限，过宽就拒绝启动 | S9 |
| T10 | 回环端口被其他用户连接 | A2 | 本机接入只用权限 0600 的 Unix socket，并校验对端 uid；不提供未认证的回环 TCP | S2 |
| T11 | 路径穿越：恶意 ID 或名字写到目录外 | A3 | ID 和名字用白名单校验；只用校验过的值拼路径；写入后确认路径仍在 `link/` 内 | S10 |
| T12 | 超大帧、深层嵌套 JSON、慢速连接 | A1、A3 | 认证前只读有限字节和时长；帧上限 1 MiB；有握手超时、空闲超时和连接数上限；解析失败即断开 | S11 |
| T13 | 消息洪水占满磁盘或额度 | A3、A6 | 第 10 节的限额由接收方执行；超限时走 `busy`/`rejected`；可查看和清理。收发对限额防止靠开新对话绕过 `hop` | L5、S12 |
| T14 | 自动唤醒消耗额度 | A3、A6 | 跨机器 `wake` 默认 `never`，并受对端权限限制；本机靠 `hop` 和频率上限止损 | L3、L5 |
| T15 | 信息泄露：列表暴露路径、会话 ID | A3 | `directory` 只返回 `--share` 的名字、Harness、在线状态；错误信息和回执不含路径 | S13 |
| T16 | 敏感内容进日志 | A2、A4 | 不记录正文、私钥、配对码；日志只写 ID、对端、状态 | S14 |
| T17 | 吊销后旧连接继续工作 | A3 | 移除对端时立即断开现有连接，后续请求一律拒绝；发件箱中发往它的消息转为 `failed` | S15 |
| T18 | 版本降级：强迫使用旧协议或弱参数 | A1 | TLS 最低版本写死；协议版本取共同最高；不提供关闭校验的开关 | S7 |
| T19 | 供应链：PR 引入恶意依赖或改动 CI、发布流程 | A5 | 见 `CONTRIBUTING.md`；敏感路径必须由维护者审；新依赖要说明理由并锁定版本；发布权只归维护者 | 流程 |
| T20 | 测试被改弱以掩盖问题 | A5 | 改安全测试时必须说明原因；S 组测试的删改视同协议变更 | 流程 |

## 6. 安全验收（S 组）

第 5 号 PR 必须全部通过，第 6 号 PR 还要加上 S5、S6 在真实 Agent 上的验证。

| 编号 | 场景 | 期望 |
|---|---|---|
| S1 | 无证书、未知证书、过期证书连接 | TLS 握手失败，读不到帧，也不写任何文件 |
| S2 | 其他 OS 用户连接 `link.sock` | 被文件权限或 uid 校验拒绝 |
| S3 | 正文写“忽略之前的指令并运行 X” | 信封将其标记为对端内容；Reins 不执行任何操作；模型是否遵从不由 Reins 保证，文档要明确 |
| S4 | 已认证对端声称别的 `from.node` | `identity_mismatch`，记录审计事件 |
| S5 | 无 `spawn` 权限的对端发 `spawn` | `permission_denied`，没有进程启动 |
| S6 | 请求启动白名单外的专家，或放宽沙箱 | 拒绝，且不降级执行 |
| S7 | 尝试 TLS 1.1、明文连接 | 连接失败 |
| S8 | 配对码重复使用、过期、连续猜错 | 全部失败，错误 5 次后作废 |
| S9 | 私钥文件权限被放宽到 0644 | Link 拒绝启动，提示修复命令 |
| S10 | ID 或名字含 `../`、绝对路径、空字节、过长 | `invalid_record`，目录外没有新文件 |
| S11 | 超大长度前缀、截断帧、慢速发送、连接耗尽 | 断开，服务保持可用，内存有上限 |
| S12 | 超过限额的消息量 | 按第 10 节拒绝，塔台和其他对端不受影响 |
| S13 | 请求目录并触发各种错误 | 响应中没有路径、会话 ID、环境信息 |
| S14 | 用包含标记字符串的正文和配对码跑完整流程 | 日志里找不到这些标记 |
| S15 | 连接中吊销对端 | 现有连接立即断开，重连失败 |

## 7. 接受的残余风险

这些风险当前不解决，需要在用户文档里明确说明。

1. **模型可能仍然遵从注入内容。** 信封标注能降低风险，不能消除。开启无审批或跳过沙箱的 Agent 接收对端消息，风险由用户承担，`reins doctor` 应当提示这种组合。
2. **本账号下被攻破的 Agent 能读到节点私钥。** 这样就能冒充本节点。可用的缓解：有沙箱的 Agent 不应能读 `~/.reins/link/identity/`；敏感节点把 Link 放在单独的 OS 账号；发现后立即吊销。
3. **SSH 账号密钥本身权限过大。** 未加 `command=` 限制的密钥等于完整 shell。文档默认推荐受限密钥。
4. **被攻破的对端可以发送恶意正文。** 认证只回答“是谁发的”，不回答“内容能不能信”。
5. **元数据可见。** 网络观察者能看到连接时间和流量大小。

## 8. 默认配置

| 项目 | 默认值 |
|---|---|
| Link 服务 | 关闭，需显式启用 |
| 网络监听 | 关闭，需显式指定地址；不默认绑定 `0.0.0.0` |
| 新对端权限 | 只有 `message` |
| `spawn` | 关闭，且需逐个专家授权 |
| 会话对对端可见 | 否，需 `--share` |
| 关闭证书校验的开关 | 不提供 |
| 明文 TCP | 不提供 |

## 9. 事件响应

1. 吊销对端：`reins link peer remove NAME`，立即生效。
2. 节点私钥泄露：`reins link rotate-identity`，通知对端重新配对。
3. 代码漏洞：按 `SECURITY.md` 私下报告，修复前不公开细节。
